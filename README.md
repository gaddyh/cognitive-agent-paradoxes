# cognitive-agent-paradoxes

> Monolithic tool-calling agents are forced to optimize contradictory behavioral objectives inside a single reasoning space. This repo proves that claim experimentally — and shows what decomposition costs, not just what it buys.

## Core Thesis

The thesis reframes how agent failures should be read:

- **Precision and recall are not just metrics** — they are observable cognitive tensions.
- **A confusion matrix is not just evaluation output** — it is a map of semantic collisions inside a system's reasoning space.
- **Datasets are not collections of examples** — they are behavioral worlds.

## Core Claim

Some agent failures are not model failures. **They are optimization-geometry failures.**

A monolithic agent compresses incompatible behavioral objectives into a single optimization space, producing unstable tradeoffs, regressions, and semantic collisions. The claim this repo tests: **decomposing the reasoning space into coherent behavioral spaces shifts the Pareto frontier** — improving one objective without forcing the regression a monolithic agent would suffer.

## Reproducing These Results

```bash
# Setup
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# 1. Baseline: monolithic tool-calling agent
python -m src.baseline.run --data data/ --out reports/baseline/

# 2. Optimize the monolithic agent (prompts / DSPy programs / routing)
python -m src.optimization.run --data data/ --out reports/optimized/

# 3. Decompose into coherent behavioral spaces and re-evaluate
python -m src.decomposition.run --data data/ --out reports/decomposed/

# 4. Generate the comparison table above
python -m src.analysis.compare --reports reports/ --out reports/comparison.md

# Run tests
pytest
```

> Adjust the module paths to match your actual entry points before publishing.

Evaluation runs on frozen `train` / `dev` / `test` splits (`data/*.jsonl`) so that decomposition decisions are made on `train` only and measured on held-out `test`, guarding against overfitting the behavioral world to the split.

## Why This Happens

The rest of this README explains the mechanism behind the numbers above.

### The conflicting objectives

A production tool agent simultaneously tries to optimize objectives that pull against each other:

| Improving…             | …often worsens                 |
| ---------------------- | ------------------------------ |
| tool-call recall       | false-positive tool activation |
| autonomous completion  | hallucinated arguments         |
| clarification behavior | task completion speed          |

Inside a single reasoning space, the model has no way to satisfy these independently — so it trades one off against another, often invisibly.

### 1. Behavioral Worlds

Datasets here are treated as behavioral specifications, not training data. Each one intentionally contains ambiguous cases, semantic overlaps, near-miss intents, conflicting optimization pressures, clarification boundaries, and hallucination traps. The dataset *defines the behavioral world the agent must survive inside.*

### 2. Observable Cognitive Tensions

Evaluation metrics are read as projections of internal reasoning tensions:

| Metric behavior                       | Underlying tension            |
| ------------------------------------- | ----------------------------- |
| High recall, low precision            | Over-triggering behavior      |
| High clarification rate               | Low autonomous confidence     |
| High completion rate + hallucinations | Argument fabrication pressure |
| Tool confusion clusters               | Semantic collision regions    |

### 3. Confusion Matrices as Semantic Maps

Confusion matrices are analyzed as semantic overlap maps, reasoning-boundary failures, and behavioral collision zones. The question becomes *"which cognitive regions are collapsing into each other?"* rather than *"which rows are incorrect?"*

### 4. Pareto Limits in Monolithic Agents

Monolithic agents repeatedly hit tradeoffs where improving one objective degrades another — recall vs. precision, autonomy vs. hallucination avoidance, clarification vs. completion speed, flexibility vs. consistency. This is the instability the Results section quantifies.

## Experimental Flow

1. **Baseline** — run a standard monolithic tool-calling agent; measure precision, recall, F1, argument correctness, hallucination rate, clarification frequency, latency.
2. **Failure analysis** — analyze confusion matrices, regression regions, semantic collision clusters, unstable optimization behavior.
3. **Optimization** — optimize prompts, DSPy programs, routing logic, tool descriptions, and behavioral constraints; observe which metrics improve and which regress elsewhere.
4. **Decomposition** — split the monolithic reasoning space into coherent behavioral spaces (action detection, tool selection, argument extraction, missing-field detection, clarification strategy, hallucination control); re-evaluate the tradeoffs.
